Three ways to connect

Use what SAP has already built before building anything new.

The cheapest integration is the one you don't have to build or run. We always check the three options in this order, and only design a custom flow when the first two don't fit.

First choice

Run by SAP

Some connections between SAP's own cloud products come ready-made and SAP operates them. You switch them on and set them up. There's no middleware for you to run.

Examples: SAP SuccessFactors, SAP Sales Cloud, SAP Ariba, SAP Concur, SAP Field Service Management.
Second choice

Prebuilt integration content

SAP and its partners publish ready-made integration packages and documented APIs on the SAP Business Accelerator Hub. We import them into SAP Integration Suite and adapt them to your setup.

Examples: Salesforce, Microsoft, Workday, ServiceNow, other SAP systems.
When needed

A flow designed for you

For local systems and special needs, we build an integration flow in SAP Integration Suite using SAP Cloud ERP's released APIs and events, so it keeps working through every upgrade.

Examples: RAMIS VAT, local bank files, MiHCM, tea broker data, a custom app.

Monitoring

Integrations fail. You should know first.

A bank rejects a file, a customer TIN is wrong, a password expires. These things happen in every live system. What matters is that the right person is alerted straight away, the message can be fixed and resent, and nothing is lost.

Every integration we build gets monitoring and alerting before go-live, plus a written run-book that says who fixes what. When we support your system after go-live, we watch the monitors with you.

Still on SAP PI/PO?

Move your interfaces before maintenance runs out.

Many SAP customers still run their interfaces on SAP Process Integration or Process Orchestration. Mainstream maintenance for SAP PI/PO ends in 2027. SAP Integration Suite is its successor, and it includes tools that assess your current interfaces and help move them across.

We start with an inventory of what you have, retire what's no longer used, move the rest, and modernise where a flow can use APIs or events instead.

Questions we hear

Straight answers.

Do we need SAP Integration Suite?

Not always. Integrations that SAP runs, and simple direct connections, work without it. Once you connect several non-SAP systems, Integration Suite is the right place to build, run and monitor them. It is licensed separately on SAP Business Technology Platform, and we size it with you.

Will our integrations break when SAP upgrades the system?

Not if they use SAP's released APIs and events, which SAP keeps stable across upgrades. That's why we don't build integrations on internal tables or screens. We also include key interfaces in the regression tests for each release.

Can we keep our existing middleware?

Yes. SAP Cloud ERP's APIs follow open standards, so other middleware, such as MuleSoft, Boomi or Azure Integration Services, can connect to it. We'll tell you honestly where SAP's prebuilt content would save you effort.

Can you connect to systems running in our own data centre?

Yes, through SAP's secure connectivity to on-premise systems, or with Edge Integration Cell when integrations themselves must run on your own infrastructure.

How do you keep integrations secure?

Every connection has its own technical user with only the permissions it needs, encrypted transport and certificate-based authentication where the other system supports it. Personal data is only sent where there's a business reason, and every message is logged.

Does Mawkish work with the other systems too?

Yes. Besides SAP, we're partners for Salesforce, Odoo, MiHCM and Databricks, among others, so we understand both ends of many of these connections.
