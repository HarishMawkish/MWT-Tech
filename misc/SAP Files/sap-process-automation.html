Process Automation with SAP Build

Automate the busywork. Keep people for the decisions.

Every business has processes that live in email, spreadsheets and phone calls: approvals that wait for someone to come back from leave, invoices typed in by hand, supplier details checked one by one. We automate them around SAP Cloud ERP with SAP's own tools, so the work flows, people only see what needs their judgement, and every step is recorded.

When a process crosses systems

Draw the process. SAP Build runs it.

For processes beyond SAP Cloud ERP's own workflows, we build them in SAP Build's visual editor. Each process is made of a few building blocks, and Joule can draft a process, a form or a rule from a plain-language description, which we then review and refine.

Forms

Start a process or collect input, on the web or on a phone, including for people outside your company.

Decisions

Business rules in readable tables that the business can maintain, such as who approves what.

Actions

Read and write SAP Cloud ERP data through released APIs, and reach other systems through Integration Suite.

Visibility

Every instance is tracked, so you can see where work waits and how long each step takes.

Documents

Stop retyping what's already on paper.

Supplier invoices, delivery notes, bank letters and customs documents arrive as PDFs and scans in a dozen layouts. SAP's document extraction reads the fields, shows how confident it is about each one, and sends only the uncertain ones to a person.

It works in two ways. With templates, it learns a layout from samples, which suits documents you receive often. With the large language model option, it reads documents it has never seen, without a template, and is charged by use.

For Sri Lankan invoices we check what matters locally: the supplier's TIN and VAT number against your supplier records, VAT at the current rate, and totals in LKR or the invoice currency.

Software robots

Bots for the screens that have no API.

Some systems can only be used through their screens: an old payroll package, a supplier portal, a bank's website. A bot repeats the clicks and keystrokes a person would make, reliably, at any hour. SAP Build includes a recorder to capture the steps and an editor to make them robust.

Attended

Runs with a person

Started by a user on their own computer, for a task they'd otherwise do by hand. The person stays in control and reviews the result.

  • Download and file a day's bank statements
  • Copy a list of orders from a customer portal
  • Prepare a monthly report pack
Unattended

Runs on its own

Runs on a schedule or when an event happens, on a dedicated machine, and reports exceptions to a person.

  • Post a night's legacy payroll results into SAP
  • Update delivery status from a 3PL's portal
  • Reconcile a data extract every morning

Our rule: API first, bot second. A bot depends on screens staying the same, so a redesigned web page can stop it. Where SAP or the other system offers an API, we use the API. We use bots for what's left, and we monitor every bot so a failure is seen the same day. If you already use UiPath, SAP offers a UiPath add-on for SAP Build.

Where AI fits

Rules where you can. Judgement where you must.

Most of a process should follow clear rules, because rules are predictable and easy to audit. AI agents help with the steps that rules can't describe well, like reading a free-text email or weighing up a quotation. SAP calls the three patterns deterministic, agentic and hybrid workflows.

Deterministic

Fixed steps

Same path every time. Approvals, postings, notifications. Most of what we automate.

Agentic

Goal, not steps

An agent is given a goal and tools, and decides the steps. Suits research and exceptions, with a person approving the result.

Hybrid

Rules with an agent step

A fixed process with one AI step inside it, such as reading an email and proposing the next action. Usually the best fit.

An example from purchasing

A purchase order comes in above the agreed contract price. Instead of a bare approval task, the approver asks Joule why. The agent compares the order with the contract and recent orders, explains the gap, and suggests what to do. The approver still decides.

Agents run with the permissions of the person using them, and every action is logged. Developers can build agents in Joule Studio, and from SAP TechEd 2026 they can also design and run n8n workflows there.

Questions we hear

Straight answers.

Is process automation included in SAP Cloud ERP?

Flexible workflows, My Inbox and situation handling are included. SAP Build Process Automation, document extraction and AI agents are SAP Business AI Platform services, subscribed separately and sized by use. We check what you already own before proposing anything new.

Do we need UiPath or another RPA tool?

No. SAP Build has its own bots. If you already use UiPath, SAP offers an add-on that lets you use UiPath capabilities with SAP Build, so you can keep that investment.

Will automations break when SAP upgrades?

Processes that use SAP's released APIs keep working through upgrades. Bots that use screens are more fragile, which is why we prefer APIs and include every automation in the tests that run before each upgrade.

Will an AI agent approve payments on its own?

Only if you decide it should, and only within limits you set. In practice, agents prepare, check and recommend, and a person approves anything that moves money or changes a commitment.

How quickly can we see a result?

A flexible workflow can be live in days. A first SAP Build process, such as supplier onboarding, usually takes a few weeks from design to go-live. We agree the scope and timeline with you after discovery.

Can our own team maintain the automations?

Yes. Business rules, approvers and forms are designed so key users can change them. We train your team and stay available for the bigger changes.
